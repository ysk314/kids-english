# 開発検討論点（Decision Log + Open Issues）

最終更新: 2026-02-09

## 1. 目的
このドキュメントは、次の開発者が「何が確定で、何が未確定か」を最短で把握するための論点整理。

## 2. 確定済み論点（Closed）
### 2.1 プロダクト範囲
- MVP必須画面は6画面。
- 進捗トラッカーは初期リリース対象外。
- 毎週ミッションUIは非表示。

### 2.2 授業進行
- 1問ごとに `前へ/次へ` で進行（固定）。
- タイマーは45分全体のみ。
- 英語導入（BPM95）は英語本題の直前に実施。

### 2.3 第5週スライド仕様
- スライド総数は49枚。
- 日本語導入4セット固定。
- 区切りスライドを挿入。
- Endスライドを追加済み。

### 2.4 大画面表示ルール
- 日本語パートはひらがな中心。
- 英語パートは英語のみ。
- 講師向け文言（本題・深掘り等）は大画面に出さず、講師ヒント側へ配置。

### 2.5 音と演出
- 正解/不正解は外部音源を使用。
  - `mockup/assets/audio/correct.mp3`
  - `mockup/assets/audio/wrong.mp3`
- 正解/不正解演出は `◯` / `×`。
- 加点演出は `みんな` / `むつみせんせい`。
- 大画面本体と授業ランナー内プレビュー両方でエフェクト表示。

### 2.6 配信
- GitHub Pagesで配信。
- `main` pushでActionsデプロイ。

## 3. 未確定論点（Open）
### 3.1 週次展開方針
- Week6以降を「同一テンプレート拡張」で進めるか。
- 週ごとに `lessonData` を分割管理するか。

### 3.2 データ管理
- カードスタジオのデータ永続化方式（JSON/DB/CMS）。
- 画像・音素材の運用ルール（命名、版管理）。

### 3.3 授業中UX
- スコア表示位置/サイズの最終固定。
- エフェクト演出時間・強度の最適化。
- サウンドON/OFFの初期状態（授業開始時）。

### 3.4 iPad運用
- 全画面化の授業オペレーション（Safari UI回避手順）標準化。
- ミラー接続不安定時のフォールバック運用。

## 4. リスクと対策
- リスク: Pagesでのアセットパス崩れ。
  - 対策: `gh-pages` ビルドで相対パス利用、Actions後に表示確認。
- リスク: 音の二重再生。
  - 対策: 正誤音の発火元をランナーに集約。
- リスク: 講師ヒントと大画面文言の混在。
  - 対策: 文言責務を分離（児童向け/講師向け）。

## 5. 次の意思決定が必要な順序
1. Week6以降の実装単位（1週ずつ or 4週まとめ）。
2. カードデータの永続化方式。
3. 教室設定画面の正式項目（音量、表示倍率、ミラー先）。
